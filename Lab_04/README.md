# Лабораторная работа № 4. Функции и разбиение на файлы

**Вариант 19. Вычисление расстояния: перегрузки `distance` для 2D и 3D точек.**

## Ч1. Перегрузки.

### Что наблюдалось
В коде объявлены две функции с одинаковым именем `distance`:

* `distance(double x1, double y1, double x2, double y2)` — расстояние между двумя точками **на плоскости** (2D);
* `distance(double x1, double y1, double z1, double x2, double y2, double z2)` — расстояние между двумя точками **в пространстве** (3D).

При вызове `distance(0.0, 0.0, 3.0, 4.0)` компилятор выбирает первую версию (4 аргумента), при `distance(0.0, 0.0, 0.0, 1.0, 2.0, 2.0)` — вторую (6 аргументов).

### Объяснение
Компилятор различает перегрузки по **числу и типам параметров** — это сигнатура. В нашем случае все параметры `double`, поэтому единственное, что отличает версии, — их **количество**. Если бы были версии с одинаковым числом аргументов, но разными типами (например, `distance(int, int, int, int)`), выбор шёл бы по типу аргументов.

Перегрузить функцию, отличающуюся **только типом возвращаемого значения**, нельзя: `double distance(...)` и `float distance(...)` с одинаковыми параметрами имеют одинаковую сигнатуру, и компилятор не знает, какую выбрать при вызове. Такая попытка — ошибка компиляции, а не линковки.

## Ч2. Разбиение на файлы.

### Что наблюдалось
Код разложен на три файла:

* `distance.h` — заголовок с **объявлениями** функций и include guard;
* `distance.cpp` — **определения** функций (тела);
* `main.cpp` — вызовы функций.

При сборке вручную (`g++ main.cpp distance.cpp -o app`) программа работает. Если убрать `distance.cpp` из команды — ошибка линковки (см. Ч6).

### Объяснение
Заголовок нужен, чтобы `main.cpp` и `distance.cpp` «знали» о функциях, не дублируя код. Компилятору для проверки вызова достаточно **объявления** — тела на этом этапе не нужны. Тела попадают в программу на этапе **компоновки**: линковщик ищет определение `distance(2D)` во всех объектных файлах и соединяет вызов с телом.

Разбиение на файлы даёт:
1. **переиспользование** — `distance.h` можно подключить в любой другой `.cpp`;
2. **ускорение перекомпиляции** — при изменении `distance.cpp` перекомпилируется только он;
3. **командную работу** — интерфейс (`.h`) и реализация (`.cpp`) могут писаться разными людьми.
