# Лабораторная работа № 8. Динамические массивы и std::vector

**Вариант 4.** Фильтрация: сохранить в отдельный vector только числа, кратные 3,
из введённой последовательности неизвестной длины.

## Ч1. Проблема фиксированного размера массива

В части Ч1 читаем числа в массив фиксированной длины `arrSize = 5` (признак
конца ввода — число `0`) с помощью функции `readFixedArray`. Если пользователь
введёт больше 5 чисел, лишние значения **не поместятся** в массив: в коде они
отбрасываются с сообщением «Массив заполнен, значение … потеряно». При наивной
записи без проверки `count < arrSize` произошёл бы **выход за границы массива**
(undefined behavior): запись в чужую память, порча стека, возможное падение
программы. Размер обычного массива фиксируется на этапе компиляции, поэтому
заранее неизвестное количество данных — прямая проблема. Именно её решает
`std::vector`.

Сравнение `x != 0` для `double` здесь корректно: `0` — точное значение,
которое пользователь вводит как признак конца, погрешности вычислений нет.

## Ч2. Решение через std::vector

Та же задача (числа до `0`) решается чтением через `push_back` в функции
`readNumbers`, возвращающей `Numbers` — длина вектора заранее неизвестна и
ограничена только памятью.

## Ч3. Операции vector и поведение при выходе за границы

Операции Ч3 выполняются на **копии** исходного вектора
(`Numbers demo = nums;`), чтобы исходная последовательность осталась
нетронутой для Ч5.

- `size()` возвращает количество реально хранимых элементов.
- `capacity()` — сколько элементов помещается в уже выделенной памяти.
  `capacity() >= size()`, и после `push_back` capacity может вырасти с запасом
  (амортизированное O(1) на добавление: перевыделение происходит редко,
  а его стоимость «размазывается» по многим добавлениям).
- `at(i)` **проверяет границы** и бросает `std::out_of_range` при `i >= size()`.
  В программе это исключение поймано в `try/catch` и выведено сообщение.
- `operator[](i)` границы **не проверяет**: `operator[]` с индексом `>= size()`
  в демонстрации не вызывается, так как это UB.
- `pop_back()` удаляет последний элемент (size уменьшается на 1).
- `erase(it)` удаляет элемент по итератору, сдвигая последующие влево (O(n)).
  В демонстрации `erase` вызывается однократно для элемента с индексом `1`:
  `demo.erase(demo.begin() + 1)`.

## Ч4. Псевдоним типа

Введён `using Numbers = std::vector<double>;`. Он реально используется
в сигнатурах функций:
- `Numbers readNumbers(double stopValue);` — чтение;
- `void printNumbers(const Numbers& v);` — печать;
- `Numbers filterMultiplesOfThree(const Numbers& src);` — фильтрация.

## Ч5. Решение варианта 4

Функция `filterMultiplesOfThree` получает **исходный** вектор `nums`
(не испорченный операциями Ч3) и складывает в новый `Numbers` только целые
значения, кратные `3` (`value % 3 == 0`). Исходная последовательность
читается через `push_back` (Ч2), поэтому её длина заранее неизвестна —
фиксированный массив не используется.
