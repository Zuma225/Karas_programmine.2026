## Цель работы

Изучить арифметические и битовые операторы C++, переполнение целых типов, преобразование типов, работу с `std::bitset`, математическими функциями и константами.

## Часть 1. Арифметические операторы

Продемонстрированы:

- сложение;
- вычитание;
- умножение;
- целочисленное деление;
- остаток от деления;
- вещественное деление;
- составной оператор `+=`.

Для вещественного деления используется явное преобразование одного из операндов к типу `double`.

Также предусмотрена проверка деления на ноль. Если `b == 0`, программа выводит сообщение об ошибке в `std::cerr` и завершается с кодом возврата 1.

## Часть 2. Переполнение

Для демонстрации переполнения используются типы `int32_t` и `uint32_t`.

Для `int32_t` сумма вычисляется сначала в типе `int64_t`, чтобы корректно определить выход результата за диапазон `int32_t`.

Пример:

`1000000000 + 2000000000 = 3000000000`

Полученное значение не помещается в диапазон `int32_t` (максимум `2147483647`), поэтому в знаковом типе это было бы неопределённое поведение (UB).

Для `uint32_t` переполнение является определённым: результат вычисляется по модулю `2^32`.

Пример:

`4000000000 + 4000000000 = 3705032704`

Механика: в памяти все биты равны `1`, прибавление `1` вызывает перенос во всех разрядах, единица выходит за пределы разрядной сетки и отбрасывается, оставляя нули.

## Часть 3. Битовые операции и bitset

Для числа `n` продемонстрированы:

- побитовое И `&`;
- побитовое ИЛИ `|`;
- побитовое исключающее ИЛИ `^`;
- побитовое НЕ `~`;
- сдвиг влево `<<`;
- сдвиг вправо `>>`.

С помощью `std::bitset<32>` выводится двоичное представление числа, а также результаты каждой операции — и как число, и как набор битов.

Также программа определяет значение бита с индексом `k` (через сдвиг и `&`) и проверяет, является ли число степенью двойки (`n != 0 && (n & (n - 1)) == 0`).

Величина сдвига `k` проверяется: она должна лежать в диапазоне от 0 до 31, поскольку сдвиг на величину, равную или большую числа бит в типе, — неопределённое поведение.

## Часть 4. Преобразование типов

Показано различие между:

- целочисленным делением;
- C-style приведением;
- приведением с помощью `static_cast`.

При делении двух целых чисел без преобразования дробная часть отбрасывается.

При преобразовании одного из операндов к `double` результатом становится вещественное число. Второй и третий способы дают одинаковый результат, потому что в обоих случаях один операнд становится вещественным и всё выражение считается по правилам вещественной арифметики.

Разница не в результате, а в безопасности и читаемости. C-style приведение не сообщает, какое именно преобразование имелось в виду, его трудно найти поиском, и оно не проверяется так строго, как именованные приведения. `static_cast` явно называет намерение, не может случайно превратиться в снятие константности или в переинтерпретацию битов и легко ищется по имени. Поэтому в современном C++ предпочитают именно `static_cast`.

## Часть 5. Прикладная задача

Для варианта 13 необходимо вычислить период малых колебаний математического маятника:

`T = 2 · π · sqrt(L / g)`

где:

- `L` — длина маятника;
- `g = 9.8` — ускорение свободного падения;
- `π` — число пи.

Ускорение свободного падения объявлено как константа `const`.

Для вычисления квадратного корня используется `std::sqrt()` из `<cmath>`.

Точное значение числа π получается с помощью `std::acos(-1.0)`. Макрос `M_PI` не используется, потому что он не является частью стандарта C++ и на некоторых компиляторах требует специальных директив перед подключением заголовка. Способ через `acos(-1.0)` переносим между компиляторами.

Длина маятника должна быть больше нуля. При вводе `L <= 0` программа выводит сообщение об ошибке в `std::cerr` и завершает работу с кодом возврата 1.

Пример:

`L = 100`

`T = 20.0709`

## Часть 6. CE и RE на практике

**CE (Compile Error)** — ошибка компиляции. Она возникает при попытке компилятора преобразовать исходный код в исполняемую программу. При наличии CE программа не может быть успешно собрана и запущена.

Во время выполнения лабораторной работы возникла ошибка при настройке сборки, потому что файл `CMakeLists.txt` оказался пустым. Из-за этого CMake не мог корректно настроить проект.

Ошибка была найдена после проверки содержимого файла `CMakeLists.txt`. В файл были добавлены необходимые настройки проекта: название проекта, стандарт C++17, исполняемый файл и флаги предупреждений.

После исправления проект успешно собрался командой `cmake --build build`.

**RE (Runtime Error)** — ошибка выполнения. Она возникает уже после успешной компиляции, во время работы запущенной программы.

Во время выполнения лабораторной работы RE не возникала.

В качестве гипотетического примера RE можно рассмотреть деление на ноль. Если выполнить деление при `b = 0` без проверки, программа может завершиться некорректно. Компилятор такую ошибку поймать не может, потому что значение `b` становится известно только во время выполнения.

Для предотвращения такой ситуации перед делением выполняется проверка `b == 0`. Если `b` равно нулю, программа выводит сообщение об ошибке и завершает работу.
